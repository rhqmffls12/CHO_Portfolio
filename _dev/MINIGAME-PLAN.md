# 원소 미니게임 (타임어택) 분석·설계안

변신하는 30초 동안 페이지에 풀려난 아이콘(이하 **몹**)을 원소별 방식으로 모두 없애는 타임어택입니다. 목표 플레이타임은 10~15초입니다.
이 문서는 구현 전 정리입니다. 아직 코드는 바꾸지 않았습니다.

## 0. 확정 사항 (2026-11-06)

| 항목 | 결정 |
|---|---|
| 몹 그리기 순서 | **병아리 앞(위)** 에 그립니다. |
| 대상 변신 | 씨앗 20개 변신과 **뱃지 소환 변신(10씨앗) 모두** 게임을 합니다. |
| 저장 | **새로고침 후에도 유지**합니다. 뱃지 습득 상태와 기록을 함께 저장합니다(현재는 새로고침하면 뱃지가 초기화되므로, 구현할 때 다시 저장 방식으로 바꿉니다). |
| 게임 모드 | **넣지 않습니다.** 필수 모드나 선택지처럼 느껴지지 않게, 평소 변신 그대로 게임이 붙습니다. 변신 중 병아리는 이미 빠르게 쫓아가므로 필요도 없습니다(3장). |

## 2. 몹을 홈페이지 전체에 풀기: 두 방식 비교

질문: "꽃처럼 하면 되는 것 아닌가?" → **꽃처럼 할 수 있습니다.** 앞서 "화면 안에서만"이라고 한 것은 두 방식 중 하나를 추천한 것이었습니다.

| | A. 꽃처럼 페이지 전체 (문서 위치) | B. 화면 안에서만 (뷰포트 고정) |
|---|---|---|
| 몹의 위치 | 꽃처럼 페이지의 특정 자리에 속함. 스크롤하면 페이지와 함께 위아래로 지나감 | 스크롤해도 늘 지금 보이는 화면 안에 떠 있음(화면에 붙어 있음) |
| 풀려나는 모습 | 원래 아이콘 자리(카드, 툴킷, 연락처)에서 튀어나와 그 근처 페이지를 돌아다님 | 아이콘 자리에서 튀어나온 뒤 화면 안으로 모여듦 |
| 장점 | 페이지 전체가 무대라 "해방" 느낌이 큼. 꽃 수집과 같은 감각 | 모든 몹이 늘 보여서 10~15초 안에 깨기 쉬움 |
| 단점 | 화면 밖 몹은 스크롤해서 찾아야 해서 시간이 늘어남. 병아리는 화면 밖으로 밀려나면 화면 안으로 돌아오므로, 결국 사냥은 보이는 곳에서 함 | 페이지가 무대라는 느낌이 약함 |

**추천: A(꽃처럼) + 찾기 보조**
- 몹은 원래 아이콘 자리에서 풀려나고, 각자 출발한 자리에서 위아래로 화면 1.5배 높이 범위 안에서만 돌아다닙니다. 페이지 맨 끝까지 흩어지지 않아 찾기 쉽습니다.
- 화면 밖에 있는 몹은 화면 가장자리에 작은 화살표로 방향과 수를 표시합니다.
- 남은 몹 수와 시간을 늘 보여 줍니다.
- 출발 위치: 툴킷 아이콘과 연락처는 원래 자리에서 나옵니다. 카드 로고는 접힌 정보 패널 안에 숨어 있을 때가 많아서, 해당 카드 썸네일 위에서 튀어나오게 합니다.
- 10~15초 목표에 맞추려면 한 판 출전 수를 줄이는 것(5장)과 이 범위 제한이 중요합니다.

## 3. 변신 중 병아리 조작감 재분석

질문: "변신 중에는 나비를 쫓다가 쉬고 망설이는 동작이 없지 않나?" → **맞습니다. 변신 중에는 없습니다.** 앞의 분석이 틀렸습니다.

코드 확인 결과(`sumi-chick-scene.js` `updateBehaviour`):
- 변신 중(`fireMode.state.remaining > 0`)에는 `firePursuit`가 켜집니다. 이때 쉬기(settle), 멍때리기(idle), 바닥 쪼기(peck)를 매 프레임 끕니다.
- 추적은 클릭 추격과 같은 최대 속도·가속·회전을 쓰고(`fastPursuit`), 쉬었다 가는 리듬(`chaseRhythm`)도 멈춥니다.
- 나비 근처에 오면 안전하게 멈추고, 나비가 멀어지면 바로 다시 쫓아갑니다.
- 변신 중에는 나비 속도도 2배입니다(`elementBoost`).

그래서 별도의 게임 모드는 필요 없습니다. 남는 특성은 아래 정도이고, 게임 판정 값으로 맞추면 됩니다.
- 병아리는 커서를 바로 따라가지 않고 가속·회전하며 따라갑니다(약간의 지연). 몹 속도를 이 지연에 맞춰 정했습니다(5장).
- 나비에 가까워지면 멈추는 거리가 있습니다. 어둠의 "몸으로 닿기" 판정 반지름을 조금 넉넉하게(45px) 잡았습니다.
- 클릭하면 원소별 순간이동을 하고, 짧은 재사용 대기시간이 있습니다.

## 5. 부하가 생길 수 있는 부분과 해결 (자세한 설명)

### 5-1. "빛과 그림자는 한 번만 그리고, 반짝임은 투명도로만"

몹에는 꾸밈이 붙습니다. 어둠 몹의 흰 외곽 빛, 불에 달아오르는 빨간 빛, 얼어붙은 파란 테두리 같은 것입니다.
- **무거운 방식**: 빛의 크기나 번짐 정도(블러 반경)를 매 프레임 바꾸는 것입니다. 브라우저가 그때마다 몹 그림을 처음부터 다시 그려야 해서(리페인트), 몹이 많으면 프레임이 떨어집니다.
- **가벼운 방식**: 빛과 테두리는 몹을 만들 때 한 번만 그려 둡니다. 깜빡이거나 숨 쉬는 효과는 그 그림의 **투명도(opacity)** 나 **크기·위치(transform)** 만 바꿉니다. 이 둘은 이미 그려 둔 그림을 GPU가 겹쳐 보여 주기만 하면 돼서 거의 공짜입니다.
- 예: 불에 달아오르는 몹은 "빨간 빛 그림"을 미리 하나 겹쳐 두고, 노출이 쌓일수록 그 빛의 투명도만 0 → 1로 올립니다. 블러 값은 바꾸지 않습니다.
- 지금 뱃지의 숨 쉬는 빛, 큰 글씨 테두리의 깜빡임이 이 방식으로 만들어져 있습니다.

### 5-2. "충돌 판정은 매 프레임 레이아웃을 읽지 않고, 스크립트 안에서 계산한 좌표만"

충돌 판정은 매 프레임 "몹과 병아리(또는 브레스, 기둥)가 얼마나 가까운가"를 계산하는 일입니다. 위치를 어디서 가져오느냐가 성능을 가릅니다.
- **무거운 방식**: 매 프레임 각 몹 요소에게 "지금 화면 어디에 있니?"를 묻는 것입니다(`getBoundingClientRect`). 같은 프레임에 몹을 이미 움직였다면, 브라우저는 답하기 전에 페이지 전체 배치를 다시 계산해야 합니다(강제 레이아웃). 몹 11개 × 매 프레임이면 이 재계산이 반복돼 끊깁니다.
- **가벼운 방식**: 몹을 움직이는 것은 게임 스크립트 자신입니다. 그러니 각 몹의 위치(x, y)와 속도를 스크립트 변수로 들고 있다가, 그 값으로 화면에 그리고 판정에도 그대로 씁니다. 브라우저에게 묻지 않습니다.
  - 병아리·나비·입의 위치는 이미 3D 장면 안의 숫자로 있습니다. 카메라 계산(수학)만으로 화면 좌표로 바꿉니다.
  - 꽃처럼 페이지 위치를 쓰는 A 방식이면, 몹 위치는 "페이지 기준 좌표"로 들고 있다가 현재 스크롤 값(숫자 하나)을 빼서 화면 좌표로 씁니다.
  - 브라우저에게 위치를 묻는 것은 몹이 처음 풀려날 때(원래 아이콘 자리) 한 번과 창 크기가 바뀔 때뿐입니다.
- 결과: 판정은 순수한 덧셈·곱셈입니다. 몹 11개 × 얼음 기둥 64개 = 약 700번 계산이라 1ms도 안 걸립니다.

### 5-3. 그 밖의 부하

| 위험 | 해결 |
|---|---|
| 몹 56개 동시 이동 | 한 판 11개(어둠 9개)만 출전. 움직임은 transform만 바꿈 |
| 어둠 모드와 겹침(캔버스 2개 + 글씨 복제) | 몹은 단순 이미지라 추가 부담이 작음 |
| 번개 고속 이동으로 벽 통과 | 벽에서 위치를 잘라 반사. 공격 판정은 순간 선분 판정이라 영향 없음 |
| 화면 밖 몹 | 화면 밖 몹은 이동 계산만 하고 그리지 않음(가장자리 화살표만) |

선택지: 몹을 three.js 장면 안의 아이콘 판으로 그리면 더 가볍고 판정도 3D 좌표로 바로 됩니다. 대신 구현량이 늘어 1차는 DOM 이미지로 추천합니다.

- 몹 색: 검정(흰 외곽선 + 은은한 흰 빛, 한 번만 그림) 또는 흰색(검은 외곽선). 2·3단은 색이 고정이고, 출전할 때 흑백을 반반으로 나눕니다.
- 1단은 1.2초마다 흑↔백으로 바뀌고, 바뀌기 0.3초 전에 깜빡여 예고합니다.
- 병아리와 같은 색인 몹에 닿으면 깨집니다(접촉 반지름 45px). 병아리 색은 순간이동할 때마다 바뀝니다.
- 순서: 첫 몹을 먹은 색부터 흑백흑백… 순서를 지킵니다. 다음 색은 화면 표시와 병아리 머리 위 점으로 보여 줍니다.
- 순서가 틀린 색이거나 병아리와 다른 색인 몹(색이 바뀌는 큰 몹 포함)에 닿으면 깨지지 않고 병아리 반대쪽으로 밀려납니다. 시간 벌칙은 없습니다.

### 내 기록

- 원소마다 내 최고 기록 3개(초, 소수점 1자리)를 이 브라우저에 저장합니다. 뱃지 습득 상태도 함께 저장합니다.

- 기록과 뱃지를 지우는 방법은 브라우저 사이트 데이터 삭제로 안내합니다. 원하면 디버그 패널에 "기록 초기화" 버튼을 둡니다(로컬에서만 보임).

## 7. 구현 범위 (1차)

8. 검사: 원소별로 몹을 판정 범위에 두었을 때 깨지는지, 타이머·기록 저장·새 기록·실패 처리, 터치 기기 제외를 헤드리스로 확인합니다.
